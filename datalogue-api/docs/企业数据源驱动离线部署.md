# 企业数据源驱动离线部署

## 背景

Datalogue 基础环境默认内置 MySQL、PostgreSQL、SQLite 所需能力。Oracle、Hive、SQL Server、Trino、Presto、ClickHouse、BigQuery 等企业数据源驱动作为可选驱动处理：系统可以保存配置并展示能力，但缺少驱动时连接测试会返回 `DRIVER_MISSING`。

纯内网环境不能依赖运行时临时下载驱动，因此企业数据源上线前必须提前准备离线依赖包。

## 文件说明

- `requirements.txt`：基础依赖，覆盖常规开发和 MySQL/PostgreSQL/SQLite。
- `requirements-enterprise.txt`：企业数据源可选驱动清单。
- `scripts/download_enterprise_wheels.sh`：在有网构建机下载企业驱动 wheel 包。
- `wheelhouse/`：离线 wheel 包目录，构建后随部署制品进入内网；不要提交到 Git。

## 有网构建机准备

在与目标部署环境 Python 版本和操作系统尽量一致的机器上执行：

```bash
cd datalogue-api
scripts/download_enterprise_wheels.sh ./wheelhouse
```

完成后将以下内容打包进入内网制品：

```text
datalogue-api/requirements-enterprise.txt
datalogue-api/wheelhouse/
```

如果不同环境架构不一致，例如 macOS 构建、Linux 部署，建议在 Linux 构建机或 Docker 构建阶段下载 wheel，避免 native wheel 不兼容。

## 内网安装

进入内网服务器后执行：

```bash
cd datalogue-api
python3 -m pip install --no-index --find-links ./wheelhouse -r requirements-enterprise.txt
```

如果使用虚拟环境：

```bash
cd datalogue-api
.venv/bin/pip install --no-index --find-links ./wheelhouse -r requirements-enterprise.txt
```

如果目标环境没有 `python` 命令，脚本会自动选择能执行 `python -m pip` 的解释器：优先使用项目 `.venv/bin/python`，如果该解释器没有 pip，则跳过并尝试 `python3`。也可以显式指定：

```bash
PYTHON=/path/to/python scripts/download_enterprise_wheels.sh ./wheelhouse
```

离线 wheel 包和 Python 版本、操作系统、CPU 架构相关。建议用与内网部署环境一致的 Python 版本执行下载，例如目标是 Python 3.12，就使用能执行 `python3.12 -m pip` 的解释器。

如果使用内网 PyPI，可以把 `wheelhouse/` 上传到制品仓库，再将安装命令替换为内网源地址。

## 运行时诊断

后端接口 `GET /api/datasource/capabilities` 会返回每类数据源的驱动状态：

- `builtin`：Python 或基础依赖已内置，例如 SQLite。
- `installed`：当前运行环境已安装对应驱动。
- `missing`：当前运行环境缺少驱动。

前端数据源管理页会展示驱动状态。缺少驱动时仍允许保存数据源配置，但点击“测试连接”会返回 `DRIVER_MISSING`，不会导致服务启动失败。

## 驱动对应关系

| 数据源 | Python 驱动 | 说明 |
| --- | --- | --- |
| Oracle | `oracledb` | 使用 SQLAlchemy `oracle+oracledb` |
| Hive | `PyHive[hive_pure_sasl]` | 默认面向 HiveServer2 |
| Presto | `PyHive[presto]` | 使用 PyHive Presto 接口 |
| Trino | `trino` | 使用 Trino SQLAlchemy 方言 |
| SQL Server | `pyodbc` | 还需要系统 ODBC Driver |
| ClickHouse | `clickhouse-sqlalchemy`、`clickhouse-driver` | 默认使用 native 协议 |
| BigQuery | `sqlalchemy-bigquery` | 需要服务账号或环境认证 |

## 注意事项

- SQL Server 的 `pyodbc` 只是 Python 包，服务器仍需安装系统级 ODBC Driver。
- Kerberos、LDAP、BigQuery 服务账号等认证材料不应打进 wheelhouse，应通过部署密钥或环境配置注入。
- 如果某个驱动没有目标平台 wheel，构建机需要具备编译环境，或者改用企业内部已验证的 wheel 包。
- 离线包版本应和 `requirements-enterprise.txt` 保持一致，升级驱动时需要重新生成 wheelhouse 并做连接测试。
