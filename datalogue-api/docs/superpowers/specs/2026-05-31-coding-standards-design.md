# 编码规范手册设计文档

**日期**: 2026-05-31
**状态**: 已批准

## 1. 目标与范围

为 Datalogue API 项目创建一套综合编码规范手册，用于：
- 统一团队代码风格
- 保证代码质量
- 便于代码审查
- 新人入职培训

**覆盖范围**：代码风格、架构、API 设计、数据库、测试、安全、日志、错误处理、文档

## 2. 设计方案

### 文档结构

```
docs/
├── CODE_STYLE.md     # 综合规范文档
└── CHECKLIST.md      # 代码审查检查清单
```

### 工具链

| 工具 | 用途 | 状态 |
|------|------|------|
| Black | 代码格式化 | ✅ 已配置 |
| Ruff | Linting + 导入排序 | ✅ 已配置 |
| mypy | 静态类型检查 | ✅ 已添加配置 |
| pytest | 测试运行 | ✅ 已配置 |

### 规范要点

1. **代码注释**：优先使用描述性命名，注释用于解释"为什么"
2. **类型注解**：公共 API 必须标注类型
3. **中文优先**：文档和注释尽量使用中文

## 3. 实现

- `docs/CODE_STYLE.md` - 包含 10 个章节的完整规范
- `docs/CHECKLIST.md` - 代码审查检查清单
- `pyproject.toml` - 添加 mypy 配置和依赖

## 4. 执行方式

- pre-commit hook 自动格式化（可选）
- 开发者本地运行检查命令
- 不包含 CI/CD 配置

## 5. 后续步骤

1. 团队学习规范手册
2. 应用到新代码
3. 逐步改进现有代码
