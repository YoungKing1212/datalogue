# 智能问数竞品调研与设计启示

> 调研日期：2026-05-28  
> 目标：梳理国内外主流智能问数产品的核心亮点，提炼数语（Datalogue）可借鉴的设计方向

---

## 一、国内产品

### 1. 帆软 FineChatBI

**产品定位**：面向企业业务人员的对话式 BI 分析工具，在 FineBI 报表体系上叠加 AI 对话层。

**核心亮点**
- **Text2DSL 双引擎**：简单明确的问题走规则模型（全可控、快速响应），复杂模糊的问题走大模型，兼顾准确率与灵活性
- **意图可干预**：将自然语言解析结果渲染为可编辑的"意图卡"，用户可以调整指标聚合方式、删减维度、切换图表类型，而不是黑盒输出
- **输入联想**：输入过程中实时推荐匹配问题，降低用户提问门槛
- **多轮对话**：维持会话上下文，支持追问和对比分析
- **异常检测与归因**：不只回答用户问的，还能主动提示数据异常并给出归因

**我们可以学习的**
- ✅ 意图可干预的 DSL 卡片设计（用户能看到 AI 理解了什么，并纠正它）
- ✅ 简单问题走规则、复杂问题走大模型的双轨路由（对应我们的 LeadAgent Simple/Complex 分类）
- ✅ 输入联想降低用户提问门槛

---

### 2. SuperSonic（腾讯音乐开源）

**产品定位**：Chat BI + Headless BI 融合平台，语义层驱动的下一代 AI+BI。

**核心亮点**
- **Chat BI + Headless BI 统一**：同一套语义模型同时服务自然语言查询和传统 BI 报表，确保口径一致
- **Schema Mapper + Semantic Parser**：先做实体映射（把"销售额"映射到具体字段），再做语义解析，两步走提升准确率
- **内置规则解析器**：部分场景不经过 LLM，直接用规则引擎，零 Token 消耗、确定性强
- **三级权限控制**：数据集级 / 列级 / 行级，企业级权限粒度
- **问后推荐**：查询完成后自动推荐相关问题，引导用户深入探索

**我们可以学习的**
- ✅ 语义层建模方式：Dataset / Metric / Dimension 三级模型（我们已采用）
- ✅ 查询完成后的"相关问题推荐"功能，提升用户探索深度
- ✅ 规则引擎兜底：对高频标准查询提供规则路径，绕过 LLM 提速降本
- ✅ 行级权限设计，企业用户必须的能力

### 3. 腾讯云 TCDataAgent

**产品定位**：企业级数据分析智能体，在 BIRD-Bench 国际评测中位列全球第三、国内第一。

**核心亮点**
- **多轮校正循环**：SQL 执行失败后自动携带错误信息重试，最终准确率高
- **指标平台融合**：与腾讯内部指标平台深度打通，语义层有强大的指标体系支撑
- **评测驱动研发**：以 BIRD-Bench 等权威榜单为准星持续迭代，有量化的准确率目标

**我们可以学习的**
- ✅ 建立内部评测基准（golden SQL 集），准确率量化可追踪
- ✅ SQL 执行失败后的智能重试策略（我们 DSL 已设计最多 3 次重试）

### 4. 阿里云 DataWorks / DB-Surfer

**产品定位**：云原生数据开发平台 AI 化，DB-Surfer 以 59.78% 在 Spider 2.0 榜单夺冠。

**核心亮点**
- **跨库联查**：支持多数据源跨库 JOIN，不局限于单库
- **Agent 化架构**：不是单次 NL→SQL，而是多轮 Agent 迭代（查询→观察→修正）
- **与数据开发工具深度集成**：问数结果可直接沉淀为数据开发任务

**我们可以学习的**
- ✅ Agent 迭代式查询（查询→分析结果→判断是否需要追加查询），对应我们的复杂问题多 QueryGraph 拆解

### 5. 网易数帆 ChatBI

**产品定位**：结合领域大模型 + 语义层的企业级 ChatBI，联合发布"可信 ChatBI 一体机"。

**核心亮点**
- **可信 AI**：强调输出可解释、可追溯，每条结论附带数据来源和 SQL 链路
- **领域模型微调**：针对企业行业特点做 SFT，行业术语识别率显著提升
- **一体机部署**：私有化硬件方案，数据不出域，满足金融/政务合规要求

**我们可以学习的**
- ✅ 每条 AI 输出附带"数据来源 + SQL 可查"的可信链路设计，提升用户信任
- ✅ 私有化/本地模型部署路线，针对金融、政务等高合规客户

### 6. Chat2DB

**产品定位**：面向开发者的 AI SQL 开发工具，GitHub 2.3 万 Star，支持 16+ 数据库。

**核心亮点**
- **SQL-7B 专项模型**：基于 CodeLlama 微调的专用 NL2SQL 模型，Spider 准确率 77.3%
- **SQL 全链路辅助**：不只是生成，还有 SQL 解释、优化建议、索引推荐、慢查询分析
- **多数据库方言支持**：MySQL/PG/Oracle/SQLServer/Hive/ClickHouse/DM 全覆盖
- **开发者友好**：嵌入 IDE 工作流，SQL 开发场景深度整合

**我们可以学习的**
- ✅ SQL 解释功能：执行后 AI 用自然语言解释"这条 SQL 做了什么"，帮业务用户理解结果
- ✅ 数据库方言适配层设计（对应我们的 DslCompiler 多方言输出）

## 二、国际产品

### 7. ThoughtSpot Spotter 3

**产品定位**：企业级 Agentic Analytics 平台，从"搜索式 BI"演进到"多 Agent 协同分析"。

**核心亮点**
- **多 Agent 角色分工**：SpotterModel（数据工程师）、SpotterViz（分析师）、SpotterCode（开发者）、Spotter 3（核心推理引擎）——不同角色用不同 Agent，术业专攻
- **Spotter Semantics**：专利的 search-token 架构 + ThoughtSpot Modeling Language，将自然语言问题确定性地翻译为 SQL，杜绝语义漂移
- **端到端 Agentic 工作流**：从问题提出到洞察生成到行动建议，全链路 Agent 覆盖
- **与 Snowflake/Databricks 深度集成**：在数据平台内原生运行，数据不移动

**我们可以学习的**
- ✅ 角色分工的多 Agent 设计思路（LeadAgent + 专项子 Agent）
- ✅ Semantics 层用建模语言（类似 DSL）将 NL 确定性地映射到 SQL，避免 LLM 随机性
- ✅ 行动建议（Insight to Action）：不只给数据，还给下一步行动推荐

### 8. Seek AI（已被 IBM 收购）

**产品定位**：面向现代数据栈的 Agentic AI 平台，主打实时问答和持续自学习。

**核心亮点**
- **自适应学习**：每次用户交互后自动改善查询准确率，越用越准
- **Snowflake Native App**：在 Snowflake 安全托管环境内运行，数据零泄漏
- **嵌入式 Data Agent**：以 API 形式嵌入第三方产品，B2B 分发路线

**我们可以学习的**
- ✅ 用户反馈驱动的自学习机制：用户纠正一次，下次同类问题自动改善（RAG 知识库更新）
- ✅ 嵌入式 API 模式：数语可提供 SDK/API，让客户把问数能力嵌入自己的系统

---

### 9. Vanna.ai

**产品定位**：开源 RAG-based NL2SQL 框架，面向开发者的嵌入式文本转 SQL 组件库。

**核心亮点**
- **RAG 驱动的 Schema 感知**：把 DDL、注释、历史 SQL 样例都向量化存储，检索后注入 Prompt，大幅提升准确率
- **训练即更新**：数据团队可以持续向 RAG 库添加 SQL 样例、业务规则，模型无需重新训练
- **2.0 新增 RBAC + 行级安全**：企业级安全能力，可按角色限定可查数据范围
- **可嵌入 UI 组件**：前端组件开箱即用，开发者直接集成

**我们可以学习的**
- ✅ RAG 知识库同时存 DDL + 注释 + SQL 样例 + 业务规则，多层次上下文注入
- ✅ 数据团队可持续维护 SQL 样例库作为"先验知识"，降低 LLM 幻觉

---

### 10. Tableau Pulse

**产品定位**：Salesforce 旗下，将 BI 从"被动查询"变为"主动推送洞察"的 AI 分析层。

**核心亮点**
- **主动推送（Proactive Insight）**：不等用户来问，系统主动监控指标变化并推送到 Slack/邮件
- **异常检测 + 自动归因**：检测到指标异动后，自动分析是哪个维度导致的
- **多指标复合提问**：支持跨指标的复杂自然语言问题，返回带上下文的 AI 解读
- **融入工作流**：Slack/邮件直接触发和回答，降低使用门槛

**我们可以学习的**
- ✅ 主动洞察推送：定时跑指标监控，异常自动触发分析并通知用户（对应我们未来的调度报告模块）
- ✅ 异常检测 + 归因分析：问数不只"查数"，还要解释"为什么"

---

### 11. Metabase Metabot

**产品定位**：开源 BI 工具的 AI 增强，轻量、自托管友好。

**核心亮点**
- **Slack 集成**：在 Slack 内直接问数、得到图表，嵌入团队工作流
- **双 Agent 架构**：QueryDesigner Agent（理解意图）+ QueryArchitect Agent（生成 SQL），职责分离
- **轻量自托管**：完全可在自己服务器上运行，中小企业低成本起步

**我们可以学习的**
- ✅ 即时通讯集成（Slack/钉钉/企微），让问数发生在用户的日常工作场景中

---

### 12. Querio

**产品定位**：面向数据团队的"有治理的 NL2SQL"，强调语义一致性和指标口径统一。

**核心亮点**
- **Context Layer**：数据团队预先定义指标关系和业务规则，所有查询都基于统一口径——问"转化率"一定用统一公式，不因 LLM 随机而漂移
- **数据团队审核工作流**：AI 生成的 SQL 可进入审核队列，数据团队批准后才进入"可信查询库"
- **指标版本管理**：指标定义变更后，历史查询结果保持可追溯

**我们可以学习的**
- ✅ Context Layer / 语义层的"口径治理"理念（对应我们的语义层，防止指标定义不一致）
- ✅ AI 生成 SQL 的人工审核工作流，提升企业信任度
- ✅ 指标版本管理，支持历史口径追溯

## 四、数语的差异化定位建议

根据竞品分析，当前市场的共同弱点是：

1. **黑盒输出**：大多数产品不展示 AI 的"理解过程"，用户无从纠正
2. **口径不一致**：没有强语义层约束时，同一个问题在不同时间可能返回不同结果
3. **缺乏可信链路**：结论无法追溯到原始数据和 SQL
4. **企业部署复杂**：权限、私有化、审计日志都是痛点

**数语的差异化应聚焦于**：
- **透明可干预的 AI 过程**（DSL 可视化 + 意图卡确认）
- **语义层保证口径严格一致**（指标/维度定义一次，全局生效）
- **完整可信链路**（NL → DSL → SQL → 结果，每步可审计）
- **LeadAgent 驱动的复杂问题自动拆解**（竞品普遍欠缺的能力）
