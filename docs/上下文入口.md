# Datalogue Agent 上下文入口

用途：给 Codex、Claude Code 等 Agent 做任务路由，避免把项目记忆、长计划和大源码文件默认塞进上下文。

## 启动规则

1. 先读根目录 `AGENTS.md`。
2. 需要判断任务域时读本文档。
3. 代码探索优先用 `.codegraph/`，再考虑 `rg` 和直接读文件。
4. `.codex/project-memory.md` 只按关键词检索，不全文读取。
5. `docs/superpowers/` 长计划只在继续对应任务时读取。
6. 修改关键代码时同步补充中文关键行级注释，优先写在方法调用或关键操作同一行，重点解释业务边界、跨层状态、fallback 和异常降级。

## 文档目录约定

- `docs/product/`：面向业务、项目负责人和交付场景的项目介绍、阶段总结。
- `docs/architecture/`：系统设计、执行链路和架构边界。
- `docs/observability/`：Langfuse、Trace、本地观测和 generation metadata。
- `docs/agent-planning/`：LeadAgent、SubAgent、语义资产注入、评估和测试计划。
- `docs/deliverables/`：可直接交付或阅读的 DOCX 成品。
- `docs/assets/`：文档图片、链路图和截图素材。
- `docs/archive/`：已被拆分、重复或过期的旧交付物，仅供追溯。

## 项目记忆检索

只在这些场景读取 `.codex/project-memory.md`：

- 回顾历史完成情况
- 查找历史验证命令或残留风险
- 确认某功能是否已经做过
- 完成任务后追加记录
- “最新详细记录”超过 10 条时，把较早记录压缩到历史区；历史压缩条目超过 10 条时，继续深度压缩为主题摘要。

推荐：

```bash
rg -n "关键词1|关键词2|文件名" .codex/project-memory.md
```

避免：

```bash
sed -n '1,9999p' .codex/project-memory.md
```

## 验证选择

- 后端：相关 pytest，必要时真实 `/api/chat/stream`
- 前端：`npm run lint`、`npm run build`，必要时真实页面
- 多轮：ConversationStore / `_thread.last_success_task`
- 可观测：SSE step、response metadata、Langfuse trace 或本地 trace index
- 数据集治理：真实接口和工作台页面
