# 数语 1.2.0：指标与维度语义查询

## 版本定位

`1.2.0` 引入业务语义层。用户不再必须说出数据库字段，而是可以使用“工作日志数量”“项目投入工时”“合同金额”等业务指标，并按时间、组织、项目、客户等维度完成分组分析。

本版本累计包含单表与简单多表能力。指标和维度必须来自真实配置与明确口径，不能只依赖提示词让模型临时推断。

## 新增能力

- 识别已定义的业务指标及其字段、聚合方式、单位和过滤口径；
- 识别时间、组织、人员、项目、客户、状态等已定义维度；
- 按一个或多个维度对指标分组；
- 支持指标排序、Top N 和时间范围过滤；
- 支持稳定范围内的多指标查询；
- 对名称相近或口径不明确的指标发起澄清。

## 能力限制

- 仅支持已经登记并验收的指标和维度；
- 未定义指标不得由模型自行创造计算口径；
- 多表指标仍需使用明确数据关系；
- 同比、环比、派生指标等能力只有在真实实现并完成验收后才能纳入演示；
- 子智能体协作过程仍不对用户展示；
- Report Worker、智能报告和完整可观测能力不属于本版本。

## 推荐演示问题

1. “统计各部门 2024 年的工作日志数量。”
2. “按月份查看各项目投入工时。”
3. “统计各部门人均工时，并从高到低排序。”（仅在该指标已真实配置时使用）
4. “对比各项目的合同金额和回款金额。”（仅在两个指标均已真实配置时使用）
5. “统计各部门的金额。”用于验证系统能澄清合同金额、回款金额或其他口径。

正式演示前应根据实际已配置指标筛选题目，不得为了演示临时宣称不存在的业务口径。

## 启动配置

```env
DATALOGUE_DEMO_CAPABILITY_LEVEL=semantic_metrics
ENABLE_REPORT_WORKER=false
ENABLE_REPORT_UI=false
ENABLE_RAW_THINKING=false
ENABLE_FULL_OBSERVABILITY=false
```

演示环境必须加载本期指标、维度、关系和演示问题清单。服务端开放 Metrics、Group By 与必要的受控修复，但对前端继续投影为统一的安全查询进度。

## 验收标准

- `1.1.0` 的单表和简单多表查询回归通过；
- 每个演示指标均能追溯到确定字段、聚合方式、单位和业务说明；
- 分组、筛选、排序和 Top N 结果与人工核算一致；
- 未定义或歧义指标不会被系统擅自解释，而是安全拒绝或发起澄清；
- 前端不暴露子智能体身份、SQL、Schema、QueryPlan 和 Raw Thinking；
- Report Worker 保持禁用，不生成智能报告。

## 下一期预告

`1.3.0` 将把当前隐藏在统一查询体验下的专业分工显性化：由主智能体负责任务理解和编排，BI 子智能体负责数据识别、查询规划、执行与受控修复。
