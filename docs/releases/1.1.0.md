# 数语 1.1.0：简单多表关联查询

## 版本定位

`1.1.0` 将问数范围从“一张表内找数据”升级为“基于已知关系组合多张表的数据”。本期强调受控关联：关系与关联键必须有配置或可靠证据，系统不能凭模型猜测表关系。

本版本累计包含 `1.0.0` 的单表查询能力，但仍不向用户展示子智能体身份。

## 新增能力

- 识别问题涉及的两张表，稳定场景下可支持少量三表查询；
- 使用明确配置的关系和 Join Key 完成关联；
- 跨表选择字段、筛选和排序；
- 基于关联结果进行简单计数或汇总；
- 对缺少关系、关联键不明确或超出表数量的问题进行安全拒绝。

## 能力限制

- 演示以两张表为主，最多表数以代码策略为准；
- 只允许使用已经配置或检索到的明确关系；
- 不允许模型臆测 Join Key；
- 暂不开放业务指标定义、维度建模和复杂指标口径；
- 不展示 Leader、BI Worker、Repair 或内部工具事件；
- 原始 SQL、Schema、QueryPlan 和数据库错误始终隐藏。

## 推荐演示问题

应根据实际演示数据集关系选择问题，例如：

1. “查询杨凯参与的项目及对应工作日志。”
2. “查询各部门人员和他们最近的工作记录。”
3. “查询项目名称、参与人员和投入工时明细。”
4. “查询每份合同对应的客户名称。”

现场问题应优先使用两张表、关系唯一且关联键明确的场景。

## 启动配置

```env
DATALOGUE_DEMO_CAPABILITY_LEVEL=multi_table
ENABLE_REPORT_WORKER=false
ENABLE_REPORT_UI=false
ENABLE_RAW_THINKING=false
ENABLE_FULL_OBSERVABILITY=false
```

演示数据集需预先配置表关系和关联键。服务端开放 Join 与 Supporting Entities，同时继续拒绝 Metrics、Group By 和未定义关系。

## 验收标准

- `1.0.0` 的单表查询回归通过；
- 推荐的两表问题返回结果与手工 SQL 或数据库结果核对一致；
- 查询计划中的每个 Join 都能追溯到明确关系与关联键；
- 无 Join Key、关系不明确或超过上限时停止执行并给出安全提示；
- 前端仍只展示统一查询进度，不暴露子智能体身份和内部载荷；
- Report Worker 保持禁用。
