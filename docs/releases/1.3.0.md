# 数语 1.3.0：子智能体显性协作

## 版本定位

`1.3.0` 将成熟的 Agent Team 专业分工正式投影为用户可理解的协作过程。主智能体负责理解问题、选择专业能力和组织最终答案；BI 子智能体负责数据集识别、字段与关系取证、查询计划、执行和受控修复。

第四期的重点不是声称本期才开始使用子智能体，而是把前三期已经稳定复用的底层协作机制产品化、显性化，并保持业务安全边界。

## 新增能力

- 显示主智能体分析问题和委派 BI 子智能体的安全摘要；
- 显示 BI 子智能体识别数据集、分析字段关系、生成计划和执行查询的阶段；
- 查询失败时显示脱敏后的受控修复状态；
- BI 子智能体返回查询产物后，由主智能体组织最终用户答案；
- 支持能够组合多表、指标、维度、筛选、排序和 Top N 的复杂问数任务。

推荐向用户展示的过程：

```text
主智能体正在分析问题
已委派 BI 子智能体处理数据查询
BI 子智能体正在选择相关数据集
正在分析字段和数据关系
正在生成并执行查询计划
查询完成，主智能体正在整理答案
```

## 能力限制

- 只展示业务可理解的阶段摘要，不展示模型原始思考；
- 不展示 SQL、完整 Schema、QueryPlan JSON、未清洗原始行或数据库原始错误；
- Repair 只展示“正在核对并修正查询计划”等安全状态；
- 智能报告和 Report Worker 尚未完成，不作为子智能体能力展示；
- 完整链路可观测平台和生产部署闭环不属于本版本；
- 子智能体不得绕过前三期的数据关系、指标口径和查询安全约束。

## 推荐演示问题

1. “统计 2024 年各部门参与项目的总工时，按照季度展示，并找出投入最高的三个部门。”
2. “查询各部门人员参与项目的日志数量，并按月份汇总。”
3. “帮我统计各部门的金额。”用于展示主智能体或 BI 子智能体对指标口径发起澄清。
4. 准备一个可受控修复的查询，用于展示系统发现字段或关系问题后修正计划并重新执行。

复杂问题必须提前用真实数据验证。Repair 演示应使用可重复的受控场景，不能依赖现场随机失败。

## 启动配置

```env
DATALOGUE_DEMO_CAPABILITY_LEVEL=agent_team
DATALOGUE_EXPOSE_AGENT_PROGRESS=true
DATALOGUE_EXPOSE_WORKER_IDENTITY=true
DATALOGUE_EXPOSE_REPAIR_PROGRESS=true
DATALOGUE_REPORT_WORKER_ENABLED=false
DATALOGUE_DEBUG_STREAM_RAW_THINKING=false
AGENTSCOPE_OTEL_TRACING_ENABLED=false
VITE_DATALOGUE_DEMO_CAPABILITY_LEVEL=agent_team
```

服务端是能力和可见性的真相源。前端根据后端能力清单投影协作阶段，不能自行通过环境变量猜测或仅用样式隐藏敏感内容。

## 验收标准

- `1.2.0` 的单表、多表、指标与维度查询回归通过；
- 主智能体到 BI 子智能体的委派、执行、产物回传和最终回答链路完整；
- 准备的复杂问题结果与人工核算一致；
- 受控 Repair 场景能够停止错误计划、完成修正并返回正确结果；
- 页面只出现批准的安全阶段摘要，敏感内部载荷没有进入 SSE、历史消息或最终答案；
- Report Worker 不被注册或触发，智能报告入口不可见；
- 不把调试 Timeline、监控面板或部署状态描述为已完成产品能力。

## 后续方向

在四期问数能力稳定后，再分别规划和验收报告子智能体、可观测治理及生产部署。只有完成真实链路验收的能力，才能进入后续正式版本说明。
