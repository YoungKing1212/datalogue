# 数语平台登录认证设计方案

> 版本：v1.0
> 状态：待评审
> 日期：2026-07-09

## 1. 背景与目标

当前系统尚无登录能力。目标是在不大改现有架构的前提下，补齐以下能力：

- 用户登录与退出登录
- Access Token 鉴权
- Refresh Token 静默续期
- 前端路由守卫
- 用户归属数据写入（以会话数据为主）

## 2. 方案选型结论

结合现有项目技术栈（FastAPI + 同步 SQLAlchemy + React + Ant Design），采用：

- 后端：基于现有依赖自建轻量 JWT 认证
- 前端：基于现有 Ant Design 页面体系实现登录页与鉴权上下文

不采用以下方案的原因：

- FastAPI Full Stack Template：更适合新项目脚手架，不适合迁入已有成熟仓库
- FastAPI Users：默认偏向 async 会话模式，当前项目为同步 Session，迁移成本高
- shadcn/Tailwind：当前前端已统一 Ant Design，引入第二套 UI 体系会增加维护成本

## 3. 与现有代码的贴合点

- 后端已具备 JWT 与密码哈希依赖（python-jose、passlib）
- 会话模型已预留 user_id 字段，可作为用户归属锚点
- 前端已有统一 API 客户端，可集中注入 Authorization 头

## 4. 认证架构设计

### 4.1 双令牌策略

- Access Token：短时效（建议 30 分钟），由前端内存保存
- Refresh Token：长时效（建议 7 天），通过 HttpOnly Cookie 存储

收益：

- 降低 Token 被脚本窃取风险（Access 不落 localStorage）
- 保持较好体验（可静默续期）

### 4.2 关键流程

1. 用户提交账号密码到登录接口
2. 后端校验密码并签发 Access Token
3. 后端下发 Refresh Token 到 HttpOnly Cookie
4. 前端请求业务接口时自动附带 Bearer Access Token
5. Access 过期时尝试调用 refresh 接口获取新 Access
6. refresh 失败则跳转登录页

## 5. 后端改造清单

### 5.1 新增模型

- 新增 User 模型（建议表名 app_user，避免与数据库关键字冲突）

核心字段建议：

- id、username、email、hashed_password
- is_active、is_superuser
- created_at、updated_at

### 5.2 配置项扩展

在配置中新增：

- ACCESS_TOKEN_EXPIRE_MINUTES（默认 30）
- REFRESH_TOKEN_EXPIRE_DAYS（默认 7）
- AUTH_COOKIE_SECURE（生产 true）
- AUTH_COOKIE_SAMESITE（建议 lax）
- BOOTSTRAP_ADMIN_USERNAME
- BOOTSTRAP_ADMIN_PASSWORD

### 5.3 安全工具函数

在安全模块补齐：

- hash_password
- verify_password
- create_access_token
- create_refresh_token
- decode_token

### 5.4 鉴权依赖

新增通用依赖：

- get_current_user：校验 Access Token 并注入当前用户
- get_current_superuser：管理员路由复用

### 5.5 认证接口

建议新增以下接口：

- POST /api/auth/register
- POST /api/auth/login
- POST /api/auth/refresh
- POST /api/auth/logout
- GET /api/auth/me

### 5.6 CORS 修正

由于 refresh 依赖 Cookie，需注意：

- allow_credentials=true 时，allow_origins 不能为 *
- 必须配置明确前端域名白名单

### 5.7 数据迁移

通过 Alembic 生成并执行 user 表迁移。

## 6. 前端改造清单

### 6.1 认证上下文

新增认证上下文模块，统一管理：

- accessToken
- currentUser
- login/logout/refresh
- 启动阶段静默登录状态（ready）

### 6.2 API 客户端增强

在现有客户端中：

- 自动附带 Authorization 头
- 401 时自动尝试 refresh
- refresh 成功后重放一次请求

### 6.3 登录页

使用 Ant Design Form 实现登录页，保持界面风格一致。

### 6.4 路由守卫

新增 RequireAuth 组件：

- 未登录跳转 /login
- 已登录进入主应用壳

### 6.5 顶栏用户信息

在 TopBar 增加：

- 当前用户名展示
- 退出登录按钮

## 7. 安全要求

- 密码仅存 bcrypt 哈希，不记录明文
- 生产环境强制 HTTPS
- SECRET_KEY、管理员初始密码必须来自环境变量
- 登录失败提示统一，避免用户枚举
- 后续可加登录限流与失败锁定

## 8. 分阶段实施计划

### Phase 1（后端最小可用）

- User 模型与迁移
- login/me 接口
- Access Token 鉴权依赖

### Phase 2（前端闭环）

- 登录页
- AuthContext
- 路由守卫
- API 客户端自动鉴权

### Phase 3（体验与安全增强）

- refresh 静默续期
- logout 清 Cookie
- 启动自动恢复登录

## 9. 验收标准

- 未登录访问业务页会跳转登录
- 正确账号密码可登录并访问受保护接口
- Access 过期后可静默续期并继续访问
- 退出登录后受保护接口返回 401
- 会话数据可正确记录 user_id

## 10. 风险与后续演进

- 若后续引入企业 SSO（OIDC/飞书/企业微信），可在现有用户体系上扩展
- 若要支持多端强制下线，可增加 Refresh Token 轮转与黑名单
- 若要细粒度控制，可追加 RBAC 权限模型
