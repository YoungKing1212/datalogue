Design Principles
6 大设计原则
每条原则来自竞品调研的真实发现——这些是同类产品的共同弱点，也是数语的差异化机会。
01
AI 意图透明可干预
将 AI 理解的意图渲染为可点击修改的 token 标签（指标 / 维度 / 时间 / 过滤），用户不再面对黑盒输出，任意修改后立即重新执行。
帆软 FineChatBI
02
全链路可信追溯
每条 AI 回答都附带完整证据链 NL → DSL → SQL → 结果，用户和数据团队随时可展开查看原始 SQL 和数据来源。
Querio网易数帆
03
语义层保证口径一致
"GMV""转化率"只有一种计算口径，所有查询都经过语义层的指标/维度定义约束，不因 LLM 随机而漂移。
SuperSonicThoughtSpot
04
越用越准的自学习
用户纠正意图或数据团队审核通过 SQL 样例，都实时更新 RAG 知识库，下次同类问题准确率自动提升。
Vanna.aiSeek AI
05
主动洞察而非被动查询
系统主动监控关键指标异动，异常时自动触发归因分析并推送通知，将数据工作从"用户来问"变为"系统来告"。
Tableau Pulse
06
复杂问题自动拆解
LeadAgent 自动判断复杂度：Simple 直接转发，Complex 拆解为并行子查询，Ambiguous 主动澄清，不让复杂问题沉默失败。
数语原创ThoughtSpot 多 Agent

Design Decisions
关键设计决策记录
记录重要选择及其权衡，方便新成员理解和未来复盘。
DD-01 · 意图卡选择 Token 标签编辑而非自然语言反问
AI 解析完用户意图后，方案 A 是渲染为可点击修改的 token 标签；方案 B 是 AI 以自然语言反问"您是想查 X 指标在 Y 维度…吗？"
✓ 选择方案 A（Token 标签）
用户一眼看出 AI 理解了哪几个要素，精准点击修改，无需多轮对话。直接复用现有 .token-tag 组件，开发成本低。
✗ 放弃方案 B（反问）
增加一轮交互延迟；自然语言描述可能产生新的歧义；用户无法知道 AI 到底理解了哪些维度。
参考：帆软 FineChatBI 意图解析卡验证了此方向 · 前端已有 .token-tag 组件
DD-02 · 知识库引入人工审核而非全自动入库
用户确认的 SQL 是否自动加入 RAG 知识库（全自动），还是经过数据团队审核后再加入（人工审核）。
✗ 放弃全自动
用户可能确认了错误的 SQL，污染知识库，导致系统越用越差。企业客户无法接受无人治理的知识库。
✓ 选择人工审核
数据团队作为知识库守门人，保证质量。审核操作极简（一键通过），知识库质量可追溯，合规客户也能接受。
参考：Querio Data Team Review · Vanna.ai 训练机制
DD-03 · Simple 问题对用户透明降级，不展示 LeadAgent 开销
LeadAgent 对 Simple 问题是否展示"正在分析复杂度"等中间状态？
✗ 放弃展示中间状态
Simple 问题的分析过程对用户没有价值，反而增加感知延迟，让用户觉得"多此一举"。
✓ 透明降级
Simple 问题直接进入 trace strip 展示 QueryGraph 节点；Complex 问题才展示"LeadAgent 正在拆解任务"进度，有意义才展示。
权衡：架构复杂度对用户体验透明，保持简单问题的流畅感
