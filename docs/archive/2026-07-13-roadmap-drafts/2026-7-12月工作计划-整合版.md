## 三、双周 Sprint 计划（12 个 Sprint，覆盖 7/14–12/26）

### Sprint 1：7/14 – 7/25 ｜ P0 「UI 体验闭环启动」

**一句话目标**：Chat 主路径完整承接 BI Tools 渲染与推理摘要，子智能体保留机制设计落地。

| 交付项 | 说明 | 角色 | 人天 |
|--------|------|------|------|
| **BI Tools 渲染（Tool UI）** | Chat 消息中展示工具运行中/成功/失败/artifact refs/安全摘要/耗时；Streamdown 流式状态接续 | 前端 | 5 |
| **Multi-Agent 可视化初版** | nested messages 展示 Leader/Worker 协作过程；reasoning 摘要只含安全业务信息，raw thinking 仅 debug gate 下可见 | 前端 | 4 |
| **子智能体会话级保留机制设计** | 一个会话 session 内，BI Worker 子 Agent 不随单轮任务结束而删除；设计 session-scoped worker pool，避免频繁 AgentCreate/TeamDelete；分析 AgentScope 2.0.3 的 session 生命周期与 agent 绑定关系 | AI 域 | 4 |
| **上下文压缩技术方案** | 基于 DeerFlow 三层中间件参考，制定 Datalogue 多轮上下文压缩方案（摘要阈值、技能包留存、工具输出外部化）；评估 AgentScope 中间件钩子可行性 | AI 域 | 3 |
| **Workbench 去常驻化收尾** | 普通 `/chat` 不挂 WorkbenchPanel；artifact 详情/失败态/retry 入口迁到 Chat 内 | 前端 | 3 |

**验收标准**：Chat 消息中可看到工具执行过程卡片、artifact 结果卡片、推理摘要；子智能体保留方案完成评审；Workbench 不再常驻。

### Sprint 2：7/28 – 8/08 ｜ P0 「主链加固 + AgentScope 观测化」

**一句话目标**：子智能体 session pool 落地，AgentScope 全链路可观测基线建立，BI Worker 关键失败类收敛。

| 交付项 | 说明 | 角色 | 人天 |
|--------|------|------|------|
| **子智能体 session-scoped pooling 落地** | 基于 S1 方案实现：同一会话 session 内复用 BI Worker agent_id；worker 空闲 TTL 到期才释放；避免每次问数都走 AgentCreate → TeamDelete | 后端 + AI 域 | 5 |
| **AgentScope 观测基线** | task_id/trace_id 贯穿 Leader session → BI Worker → 工具调用 → artifact → 最终 answer；至少覆盖 session 创建、AgentCreate、工具执行、artifact 写入四个关键节点 | 后端 | 4 |
| **BI Worker 失败类收敛** | 针对 FIELD_NOT_FOUND/FILTER_MISSING 两类最高频失败建立回归用例；校验 field_refs 自动兜底逻辑的误报率 | AI 域 | 3 |
| **Chat 页失败态 + retry 闭环** | 失败诊断卡片（safe diagnosis + recommended action）；retry 按钮触发重试，保留原 artifact refs | 前端 | 3 |

**验收标准**：同一会话连续 3 轮问数不产生新 AgentCreate 调用；task_id 可在日志中追踪全链路；5 条代表性问题 FIELD_NOT_FOUND 误报率下降。

### Sprint 3：8/11 – 8/22 ｜ P0 「上下文压缩 + OTel + 多轮优化」

**一句话目标**：多轮对话上下文不爆、OTel 链路可独立排查、多轮快速筛选上线。

| 交付项 | 说明 | 角色 | 人天 |
|--------|------|------|------|
| **上下文压缩功能上线** | 多轮对话超过阈值时自动触发历史压缩；保留技能包与关键 artifact_refs；摘要前通过 hook 把长期信息写入外部存储 | 后端 + AI 域 | 5 |
| **多轮快速筛选优化** | 已有 SQL 骨架时，后续轮次跳过完整 QueryPlan 生成，只做 filter/limit 参数替换；基于 MULTITURN_BLUEPRINT_SHORTCUT 等现有开关深化 | AI 域 | 3 |
| **OTel 链路观测补全** | Span 覆盖：task 创建 → AgentScope session → 工具执行 → SQL 编译 → DB 执行 → artifact 写入；exporter 默认关闭，排障时按窗口打开 | 后端 | 3 |
| **Tool UI 完善 + Mermaid/ECharts 渲染** | Chat 消息支持 Mermaid 流程图和 ECharts 纯 JSON option 图表渲染；图表失败时降级为数据表格 | 前端 | 4 |

**验收标准**：12 轮以上对话的 LLM 上下文 ≤ 安全阈值（128K 80%）；task_id 可串起 5 层 span；已有 SQL 的后续筛选轮次不重新生成 QueryPlan。

## 六、关键依赖与风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| AgentScope 2.0.3 不支持 session-scoped agent pooling | S2 子智能体保留无法按预期实现 | 降级为基于 Redis 的 worker agent_id 缓存层，agent 仍创建但复用 ID |
| 多轮上下文压缩与 AgentScope 中间件冲突 | S3 上下文压缩功能受阻 | DeerFlow 方案独立于 AgentScope 中间件实现，不依赖 before_model 钩子 |
| 表关系知识图谱自动提取不准确 | S4-S5 推迟 | 先手动补录 + 蓝图 call_template 作为主事实来源，自动提取为辅 |
| 多租户与现有单租户架构冲突 | S9-S11 改造面大 | 先做逻辑隔离（tenant_id column），不做物理 schema 隔离 |
| LLM 成本波动 | 全年 | S5 预编译 Query-Plan + S3 上下文压缩减少重复 LLM 调用 |
| 三人非全职，Sprint 挤压 | 全年 | 按优先级分配，P2 项目允许推迟到 2027 Q1 |
