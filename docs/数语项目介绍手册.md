# 数语（Datalogue）项目介绍手册

> 版本：v2026.06.23 | 维护人：杨凯 / Ken Yang

## 1. 项目概述

数语是一个面向企业数据的 **AI 原生智能问数平台**。与传统"预配置 SQL + 参数选择"的报表系统不同，数语以 Agent 驱动的自然语言问数为核心——业务用户用自然语言提问，系统通过语义资产解析、DSL 生成、SQL 编译执行和结果解释，给出可追溯、可审计、可复核的回答。

核心价值主张：让业务用户无需了解 SQL 或数据模型，直接用自然语言获取企业数据洞察，同时保持完整的治理链路和审计能力。

## 3. 系统架构

系统分为五层：前端层、API 层、Agent 层、治理层、可观测层。

```
业务用户
  │
  ▼
datalogue-web（React + assistant-ui）
  │ SSE /api/chat/stream    │ REST API
  ▼                          ▼
Chat API ◄──────────► Dataset / Datasource / Observability API
  │                          │
  ▼                          ▼
LeadAgent 控制面              数据集治理
  │ 路由 / 调度               │ 指标 / 维度 / 术语 / 蓝图 / Manifest
  ▼                          │
DatasetSubAgentRunner        │
  │                          │
  ▼                          ▼
LangGraph QueryGraph    Datalogue 元数据库（SQLAlchemy + Alembic）
  │
  ├─► LLM Gateway（LiteLLM）
  ├─► SQL 编译与执行 → 企业数据源
  └─► 结果解释与报告生成

DatalogueTracer → Langfuse / 本地 trace index → 查询审计页
```

### 3.1 Agent 分层设计

系统严格区分控制面与数据面：

**LeadAgent（控制面）** 负责时间理解、会话上下文管理、Manifest 路由打分、schema 状态检查、数据集级澄清和 SubAgent 调度。它不直接接触指标、维度、术语、蓝图、SQL 或字段级 schema。

**Dataset SubAgent（数据面）** 使用 LangGraph 状态图执行数据集内问数链路：多轮上下文合并 → 意图识别 → 入口分类 → 蓝图执行 → Schema 召回 → 术语归一化 → 语义资产解析 → DSL 生成 → DSL 校验 → SQL 编译 → SQL 执行 → SQL 诊断 → 报告生成。

**Runner 协议**：当前使用进程内 `InProcessDatasetSubAgentRunner`，协议已为后续跨进程 RPC 预留 trace 和 parent observation 字段。

## 6. 端到端业务链路

完整的业务流程分为治理阶段和问数阶段：

**治理阶段：** 接入数据源 → 同步 Schema/DDL → 选择源表形成语义数据集 → 字段标注（AI 辅助 + 人工确认）→ 维护指标/维度/业务术语 → 创建分析蓝图/语义验证用例 → 维护 SubAgent Manifest → Lint 通过后发布 current Manifest。

**问数阶段：** 用户自然语言提问 → LeadAgent 路由与澄清 → Dataset SubAgent 执行 QueryGraph → 生成 DSL/SQL/查询结果/报告 → 持久化消息与 trace → 查询审计页回看 → 人工反馈驱动治理资产迭代。

## 7. 核心机制

### 7.1 SubAgent Manifest 路由

Manifest 是 LeadAgent 路由的稳定契约，回答三个问题：数据集适合/不适合回答哪些问题、绑定的 schema 版本是什么。

路由规则：显式 dataset_id 返回 `locked`；否则用 `score_manifest_question()` 对所有 current Manifest 打分，自动选择阈值 0.65、领先差 0.12。路由结果为 locked / selected / ambiguous / no_match 四种。

Manifest 发布需通过 Lint 校验（description 长度与质量、sample_questions 数量、negative_examples 数量等），Schema 变更会触发 stale 标记和复核提示。

### 7.2 DSL 优先的 SQL 生成

系统先生成结构化 DSL，再编译为 SQL，而非直接让模型拼 SQL。DSL 可校验字段/指标/维度/过滤条件缺失，可承载语义资产 ID，SQL 编译器统一处理方言、只读保护和默认约束。SQL 执行失败后进入诊断流程（本地错误分类 + LLM SQL 审计），可修复则重试，不可修复则提示治理缺口。

### 7.3 多轮上下文

`ConversationStore` 管理会话状态：session lock、active dataset、pending clarification、subagent capsules、消息压缩。每轮通过 `merge_prior_context` 合并上一轮输出胶囊，支持数据集级澄清恢复和术语冲突澄清恢复。

### 7.4 可观测与查询审计

`DatalogueTracer` 封装 Langfuse SDK v4，记录从 root trace 到 LeadAgent、SubAgent、LangGraph 节点、LLM generation、SQL 诊断等全链路 observation。写入 `ObservabilityTraceIndex` 支撑数语内部查询审计页，Langfuse 不可用时降级为 no-op。

## 8. API 接口概览

### 问数与会话
`POST /api/chat/stream`（SSE 流式问数）、`GET/POST /api/conversation`（对话 CRUD）、`POST /api/messages/{id}/feedback`（反馈）

### 数据源管理
`GET/POST/PUT /api/datasource`（CRUD）、`POST /api/datasource/{id}/test`（测试连接）、`GET /api/datasource/{id}/schemas`（Schema 列表）

### 数据集治理
`GET/POST/PUT /api/dataset`（CRUD）、指标/维度/术语/蓝图/Manifest 的子资源 CRUD、术语发现与冲突检查、蓝图发布与测试

### 可观测
`GET /api/observability/summary|costs|quality|failures|traces`（审计统计与 trace 列表详情）

## 9. 数据治理对象模型

核心实体关系：

- **Datasource** → SourceTable → SourceColumn（数据源与物理表结构）
- **SemanticDataset** → SemanticMetric / SemanticDimension / BusinessTerm / AnalysisBlueprint / DatasetSubAgentManifest / SemanticValidationCase（语义数据集与治理资产）
- **Conversation** → Message（对话与消息）
- **ObservabilityTraceIndex**（可观测索引）

字段标注遵循"AI 辅助 + 人工确认"：AI 标注写入 `ai_description`、`ai_semantic_role` 等，人工覆盖写入 `user_description`、`user_semantic_role`，问数时使用 `effective_desc` 和人工确认角色。

## 10. 支持的数据源

基础版：PostgreSQL、MySQL。

企业版：Oracle、Hive、Trino、ClickHouse、BigQuery、通过 ODBC 连接的其他数据库。

所有数据源执行前有 SQL 只读守卫、方言解析、查询超时、默认 LIMIT 和时间范围约束等保护机制。
