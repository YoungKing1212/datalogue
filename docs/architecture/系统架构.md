## 二、分层职责

### 1. 前端层 (`datalogue-web/`)
- React 19 + Vite + TypeScript
- 对话 UI: assistant-ui（SSE 流式消费）
- 页面：/chat（问数中心）、/datasets（数据集治理）、/datasources（数据源）、/settings（设置）

### 2. API 层 (`datalogue-api/app/api/`)
- FastAPI 框架，注册 9 个路由模块
- 核心入口：`POST /api/agent-team/tasks/stream`（SSE 流式问数）
- 辅入口：数据集 CRUD、数据源管理、工作台、llm 配置

### 3. Agent 执行层

#### 3.1 Agent Team Runtime (`app/runtime/agent_team_runtime.py`)
- 创建 Datalogue task 真相源
- 创建 AgentScope mirror session/message
- 委托给 AgentScopeServiceTaskRunner

#### 3.2 AgentScope Runtime 集成 (`app/agentscope_runtime/`)
- **app_factory.py**: AgentScope Service 子应用创建与生命周期接入
- **runner.py**: Agent Team 网关，通过 HTTP 调用 AgentScope Service
- **client.py**: AgentScope Service HTTP 客户端
- **registry.py**: 注册 Datalogue Leader / Worker Agent 规格
- **projection.py**: AgentScope 事件 → Datalogue 事件投影
- **otel_setup.py / worker_logging.py**: 追踪初始化与 Worker 日志归一
- **credentials.py**: LLM 凭证管理

#### 3.3 BI 领域能力 (`app/domains/bi/`)
- **agent/runtime_context.py**: 组装 Dataset 工具链运行时上下文，绑定唯一受控 SQL 执行器
- **agent/native_handoff.py**: BI native handoff 入口，消费当前领域 Skill 与 runtime context
- **skill/dataset_query.py**: 数据集查询 Skill
- **skill/runtime_bridge.py**: AgentScope Dataset Runtime Bridge
- **toolkit/atomic.py**: BI 原子工具（数据集查询、SQL 编译、报告生成）
- **worker/**: QueryPlan 契约、渐进式上下文校验和 BI Worker 受控执行

旧 `app/bi/skill|toolkit` 与 `app/agents/bi_agent/runtime_context.py` 不再作为当前实现或导入入口；历史设计仅保留在 `docs/archive/` 用于审计。

### 4. 数据层

#### PostgreSQL（主元数据库）
- 表结构见 `app/models/`
- 核心模型: SemanticDataset / SemanticMetric / SemanticDimension / BusinessTerm / AnalysisBlueprint / Conversation / AgentTeamTask

#### Redis（AgentScope 支撑）
- 会话锁、消息总线、回放日志、收件箱
- 由 AgentScope Service 管理连接池

## 三、核心设计原则

| 原则 | 说明 |
|------|------|
| **控制面/数据面分离** | Leader Agent 只做编排，不直接生产 SQL |
| **DSL 先行** | 工具层先生成 DSL → 编译为 SQL，而非 LLM 直接拼 SQL |
| **Manifest 路由契约** | 每个数据集发布 Manifest，描述适合/不适合回答的问题 |
| **安全执行** | QueryPlan 契约校验 → 受控执行，失败走 RepairRequest 而非暴露原始错误 |
| **事件驱动** | AgentScope 原生事件流 → DatalogueEventEnvelope → SSE |
