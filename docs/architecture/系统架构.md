## 二、分层职责

### 1. 前端层 (`datalogue-web/`)
- React 19 + Vite + TypeScript
- 对话 UI: assistant-ui（SSE 流式消费）
- 页面：/chat（问数中心）、/datasets（数据集治理）、/datasources（数据源）、/settings（设置）

### 2. API 层 (`datalogue-api/app/api/`)
- FastAPI 框架，注册 9 个路由模块
- 核心入口：`POST /api/agent-team/tasks/stream`（SSE 流式问数）
- 辅入口：数据集 CRUD、数据源管理、工作台、llm 配置

### 3. Agent 执行层

#### 3.1 Agent Team Runtime (`app/runtime/agent_team_runtime.py`)
- 创建 Datalogue task 真相源
- 创建 AgentScope mirror session/message
- 委托给 AgentScopeServiceTaskRunner

#### 3.2 AgentScope Service 集成 (`app/agentscope_service/`)
- **runner.py**: Agent Team 网关，通过 HTTP 调用 AgentScope Service
- **client.py**: AgentScope Service HTTP 客户端
- **registry.py**: 注册 Datalogue Leader Agent 与 Worker 规格
- **tools.py**: Datalogue 自定义 Tools（候选筛选、上下文准备、schema 证据、QueryPlan 执行与 repair）
- **bi_worker_runtime.py**: BI Worker QueryPlan 受控查询执行
- **bi_worker_validator.py**: 渐进式上下文和 join / relationship 支持校验
- **credentials.py**: LLM 凭证管理
- **projection.py**: AgentScope 事件 → Datalogue 事件投影

#### 3.3 BI 工具链 (`app/bi/`)
- **toolkit/atomic.py**: BI 原子工具（数据集查询、SQL 编译、报告生成）
- **toolkit/dataset_runtime.py**: 数据集查询运行时
- **skill/dataset_query.py**: 数据集查询 Skill
- **skill/runtime_bridge.py**: AgentScope Dataset Runtime Bridge

#### 3.4 BI LeadAgent (`app/agents/bi_agent/`)
- 历史迁移与兼容服务目录，保留 handoff 端口、事件定义和部分旧服务抽象。
- 当前问数主链不再以 BI LeadAgent 为控制面；新的规划、派生和协作由 AgentScope Agent Team 的 Leader Agent 负责。

### 4. 数据层

#### PostgreSQL（主元数据库）
- 表结构见 `app/models/`
- 核心模型: SemanticDataset / SemanticMetric / SemanticDimension / BusinessTerm / AnalysisBlueprint / Conversation / AgentTeamTask

#### Redis（AgentScope 支撑）
- 会话锁、消息总线、回放日志、收件箱
- 由 AgentScope Service 管理连接池

## 三、P0 架构边界

### 唯一主链

当前唯一产品主链是 `POST /api/agent-team/tasks/stream → AgentTeamTaskRuntime → AgentScopeServiceTaskRunner → AgentScope Agent Team → BI Worker Tools`。旧 LangGraph、direct-query、legacy payload 和 BI LeadAgent 目录只允许作为历史迁移层、内部 fallback 或兼容说明存在，不再作为当前架构主语。

### Leader 控制面不可绕过

Leader Agent 是控制面，负责规划、候选确认、Worker 创建、TeamSay 汇报收敛和多 Worker 扩展边界；BI Worker Agent 是执行/诊断面，负责通过受控工具完成资产召回、QueryPlan 校验、查询执行、修复和 artifact 写入。任何提速方案都必须保留 Leader 编排，不得为了降低延迟把用户问题直接送入 BI Worker runtime 或 direct-query 产品入口。

### Repair 一等可信闭环

repair 是问数可信链路的一等能力，完整阶段为：Failure Classifier（失败分类）、Private Diagnosis（私有诊断）、Repair Planner（修复计划）、User Confirmation（用户确认）、Retry Executor（续跑执行）、Artifact Writer（产物写入）。SQL、schema、raw rows、原始数据库报错和 RepairPatch 主体只允许在 runtime/tool 私有诊断层与本地 debug 中流转；跨到 LLM prompt、SSE、用户可见回答、artifact 摘要或 OpenViking 普通上下文时，只能输出安全摘要、计数和 refs。

## 四、P1/P2 收口边界

### QueryPlan 迁移债

QueryPlan 是 BI Worker Agent 与 Datalogue Tools 之间的当前 Worker 契约；legacy DSL / legacy query plan 只是执行器兼容层和迁移债务。短期允许保留 QueryPlan 到 legacy DSL 的转换以降低切换风险，但中期必须退出双契约：要么让执行器直接消费 QueryPlan，要么定义统一的 `ControlledQuerySpec` 作为 QueryPlan、SQL 编译、repair 和 artifact 的共同契约。任何新功能不得把 legacy DSL 重新描述为未来核心路径。

### 事件三层边界

事件不再服务所有场景，按职责分三层：

| 分层 | 面向对象 | 允许内容 | 禁止内容 |
|---|---|---|---|
| 用户可见事件 | 聊天 UI / assistant-ui | 最终回答、业务摘要、候选确认、artifact 卡、可读 refs | SQL、schema、raw rows、原始报错、private diagnosis |
| Workbench 事件 | 工作台 / retry / artifact | checkpoint、artifact_ref、trace_ref、retry action、安全诊断摘要 | 可执行 SQL、RepairPatch 主体、原始数据行 |
| Debug 事件 | 后端日志 / trace / 本地排障 | Leader/Worker/Tool/DB 分层日志、private diagnosis、本地 raw debug | 默认进入 SSE 或用户可见 artifact 摘要 |

`legacy_payload` 只保留兼容，不再扩字段；新字段必须先判断属于用户可见、Workbench 还是 Debug。

### assistant-ui 近期边界

assistant-ui 迁移继续走可见层收口：稳定结果卡、artifact 展示、reasoning summary、ThreadList、会话恢复和 URL 同步。近期禁止做 headless primitives 级大重构，也不重写 assistant-ui runtime；否则会同时打散后端事件协议、前端状态、Workbench 和 artifact 链路。

### 扩展 Worker 暂缓

Report / Python / Audit Worker 是长期架构预留，不是当前扩展任务。解除暂缓至少需要满足：BI 查询一轮成功率稳定、失败能进入 repair、artifact 必定可查看、最终回答不泄露内部计划、Workbench 能回放 checkpoint、日志能区分 Leader / Worker / Tool / DB。

## 五、运行时健康检查

部署和交接前必须按 `docs/operations/运行时健康检查.md` 检查 AgentScope Service、Redis、Credential、Leader Agent、Session stream、BI Tool、Artifact API 和 Frontend version。健康检查只证明主链运行条件，不替代真实问数 smoke。

## 六、核心设计原则

| 原则 | 说明 |
|------|------|
| **控制面/数据面分离** | Leader Agent 只做编排，不直接生产 SQL |
| **DSL 先行** | 工具层先生成 DSL → 编译为 SQL，而非 LLM 直接拼 SQL |
| **Manifest 路由契约** | 每个数据集发布 Manifest，描述适合/不适合回答的问题 |
| **安全执行** | 上下文/关系校验 → QueryPlan 受控执行，失败走 RepairRequest / RepairPlanCard / checkpoint refs，而非暴露原始错误 |
| **事件驱动** | AgentScope 原生事件流 → DatalogueEventEnvelope → SSE |
